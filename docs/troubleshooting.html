Troubleshooting

This document covers common issues and their solutions when using Ork.

Connection Issues

"failed to connect to server.example.com:22"

Problem: SSH connection cannot be established.

Possible Causes & Solutions:

  1. Wrong hostname or IP — verify the host is correct. Test with: ping server.example.com
  2. Wrong port — default is 22, but your server might use a different port: 
    node.SetPort("2222")  // or your custom port
  3. SSH key not found — default key is id_rsa in ~/.ssh/. Verify: ls -la ~/.ssh/ 
    node.SetKey("your_key_file")
  4. Key permissions too open: 
    chmod 600 ~/.ssh/your_key_file
chmod 700 ~/.ssh/
  5. User doesn't exist — default user is root: 
    node.SetUser("your_username")

"host cannot be empty"

Problem: Trying to connect without setting a host.

Solution: Use NewNodeForHost() or set SSHHost explicitly:

// Correct
node := ork.NewNodeForHost("server.example.com")

// Incorrect - this creates empty host
node := ork.NewNode()

Skill Issues

"playbook 'xyz' not found in registry"

Problem: Trying to run a skill by ID that isn't registered.

Solution: Use the correct ID or run the skill directly:

// By ID (must be registered) - deprecated, prefer Run() with a direct instance
results := node.RunByID(skills.IDAptUpdate)

// Direct instance (preferred)
results := node.Run(apt.NewAptUpdate())

Check available IDs in skills/constants.go.

"username is required"

Problem: Running a user skill without required arguments.

Solution: Set the required argument:

node.SetArg("username", "alice")
results := node.Run(user.NewUserCreate())

Skill reports "Changed: false" but should have changed

Problem: Idempotency check incorrectly reports no changes needed.

Debug:

// Manually run the check command
results := node.RunCommand("your-check-command")
log.Println(results.Results["host"].Message)

SSH Authentication Issues

"host key verification failed: knownhosts: key is unknown"

Problem: The host's SSH key is not in your known_hosts file.

Solution: Add the host key to your known_hosts file:

ssh-keyscan HOST >> ~/.ssh/known_hosts
# Replace HOST with your server's hostname or IP

"host key verification failed: knownhosts: key mismatch"

Problem: The host's SSH key has changed. This could indicate a man-in-the-middle attack.

Solution: Remove the old key and add the new one:

# Remove the old key
ssh-keygen -R HOST
# Add the new key
ssh-keyscan HOST >> ~/.ssh/known_hosts

Important: Only do this if you're certain the server is legitimate and the key change is expected (e.g., server reinstallation).

"host key verification failed: knownhosts: key is revoked"

Problem: The host's SSH key has been revoked. This is a security concern.

Solution: Do not connect to this host. The key revocation indicates a security issue. Contact your system administrator.

"authentication failed: unable to authenticate"

Problem: SSH key authentication failed.

Solutions:

  1. Key not authorized on server: 
    # On server, add your public key
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
  2. Wrong key file — verify you're using the private key: 
    node.SetKey("id_rsa")  // not id_rsa.pub
  3. SSH agent not running: 
    eval $(ssh-agent -s)
ssh-add ~/.ssh/your_key
  4. Wrong user — verify the user exists on the server: 
    node.SetUser("your_username")  // Default is "root"

"SSH key exchange algorithm mismatch"

Problem: The SSH client and server do not share a supported key exchange algorithm. This can happen with modern or hardened OpenSSH servers that prefer or require algorithms not supported by golang.org/x/crypto/ssh, such as sntrup761x25519-sha512@openssh.com.

Solutions:

  1. Check the server algorithms: 
    ssh -vvv user@HOST
ssh -Q kex
  2. Configure compatible algorithms in Ork: 
    cfg := ork.NewNodeConfig().
    WithHost("server.example.com").
    WithLogin("ubuntu").
    WithKey("id_rsa").
    WithKexAlgorithms([]string{
        "curve25519-sha256",
        "curve25519-sha256@libssh.org",
        "ecdh-sha2-nistp256",
        "diffie-hellman-group14-sha256",
    })
  3. Adjust server configuration if it is too restrictive: 
    # In /etc/ssh/sshd_config
KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org,diffie-hellman-group14-sha256
systemctl restart sshd

Limitation: Ork can only configure algorithms supported by golang.org/x/crypto/ssh. It cannot enable unsupported algorithms such as sntrup761x25519-sha512@openssh.com until the underlying library supports them.

"SSH host key algorithm mismatch"

Problem: The SSH client and server do not share a supported host key algorithm.

Solution: Configure compatible host key algorithms:

cfg := ork.NewNodeConfig().
    WithHost("server.example.com").
    WithLogin("ubuntu").
    WithKey("id_rsa").
    WithHostKeyAlgorithms([]string{
        "ssh-ed25519",
        "rsa-sha2-512",
        "rsa-sha2-256",
    })

Permission Denied (publickey)

Problem: Server rejects key authentication.

Solutions:

  1. Enable key authentication on server: 
    # In /etc/ssh/sshd_config
PubkeyAuthentication yes
systemctl restart sshd
  2. Check authorized_keys permissions: 
    chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

Dry-Run Mode Issues

Changes happening in dry-run mode

Problem: Commands are executing even with dry-run enabled.

Solution: This should not happen. Ensure you're using Ork's SSH functions:

// Use ssh.Run which checks IsDryRunMode
output, err := ssh.Run(cfg, types.Command{Command: "command"})

// NOT os/exec or other methods

Dry-run mode not propagating

Problem: Dry-run set on inventory but nodes still executing.

Solution: Verify propagation is working:

inv := ork.NewInventory()
inv.SetDryRunMode(true)

// Check individual nodes
for _, node := range inv.GetNodes() {
    if !node.GetDryRunMode() {
        log.Println("WARNING: Node doesn't have dry-run mode!")
    }
}

Results and Error Handling

Results map is empty

Problem: Running operations but results.Results is empty.

Possible Causes:

  1. Wrong host key in results — results are keyed by host, not by IP: 
    result := results.Results["server.example.com"]
  2. Node not added to group/inventory: 
    group := ork.NewGroup("webservers")
group.AddNode(node)  // Don't forget this!

Cannot access Result fields

Problem: Trying to access result but getting nil pointer.

Solution: Check if host exists in results:

result, ok := results.Results["server.example.com"]
if !ok {
    log.Fatal("No result for host")
}

Group and Inventory Issues

Group operations not running on all nodes

Problem: Running skill on group but only some nodes execute.

Debug:

// Check nodes in group
nodes := group.GetNodes()
log.Printf("Group has %d nodes", len(nodes))

// Verify node configuration
for _, node := range nodes {
    log.Printf("Node: %s, Port: %s", node.GetHost(), node.GetPort())
}

Inventory results missing some hosts

Problem: Inventory Run missing results for some nodes.

Possible Causes:

  1. Max concurrency limiting: 
    // Increase if needed (default is 10)
inv.SetMaxConcurrency(20)
  2. Duplicate hosts in different groups — results from the last processed group will overwrite earlier ones.

Performance Issues

Operations are slow

Problem: Each command takes a long time to execute.

Solutions:

  1. Use persistent connections: 
    node.Connect()
defer node.Close()
// All subsequent commands reuse the connection
  2. Check network latency: 
    ping -c 10 your-server.com
  3. Use inventory concurrency for multiple nodes: 
    inv.SetMaxConcurrency(50)  // Run up to 50 in parallel

Memory usage high with many nodes

Problem: High memory usage when managing many servers.

Solution: Limit concurrent connections:

inv.SetMaxConcurrency(10)  // Don't overwhelm your system

Testing Issues

Tests fail with "connection refused"

Problem: Integration tests can't connect to test containers.

Solution: Ensure Docker is running:

docker ps
# If not running, start Docker Desktop or docker service

Mock not working in tests

Problem: SSH calls still hitting real servers in tests.

Solution: Ensure you're using SetRunFunc:

// In test
ssh.SetRunFunc(mockFn)
defer ssh.SetRunFunc(nil)

Debugging Tips

Enable Verbose Logging

import (
    "log/slog"
    "os"
)

// Create verbose logger
logger := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{
    Level: slog.LevelDebug,
}))

node.SetLogger(logger)

Inspect Configuration

// Print full configuration
log.Printf("Node config: %+v", node.GetNodeConfig())

// Print args
log.Printf("Args: %v", node.GetArgs())

Getting Help

If issues persist:

  1. Check documentation — Getting Started, API Reference, Architecture
  2. Review examples — see *_test.go files for usage examples
  3. Enable debug logging — use slog.LevelDebug for verbose output
  4. Test in dry-run mode — verify operations before running for real
